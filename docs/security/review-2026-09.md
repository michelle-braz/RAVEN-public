# Pre-commercial security review, September 2026

> Classification: Security

Scope: the whole repository at commit `0f66b49` (start of the commercial-readiness work). Method: code reading of
every module, hostile-input testing, dependency audit, secret scan of the tree and full git history, container
inspection. Each finding was reproduced (or read in code) before being fixed, and each fix has a test that fails if
the fix is reverted (verified by mutation).

| # | Finding | Severity | Resolution |
|---|---|---|---|
| 1 | API keys compared with `==` / set membership (timing side channel) | Medium | Constant-time comparison everywhere |
| 2 | Unlimited key guessing: no throttle on failed authentication | High | Lockout per client address after 10 failures a minute; 429 with `Retry-After` |
| 3 | Revoking a beta key had no effect while the process ran (keys copied into a second list at startup) | High | Single source of truth, checked on every request |
| 4 | A second, unauthenticated FastAPI app (`/ingest`, `/analyze`) existed in the pipeline module | High | Removed; the pipeline has no HTTP surface |
| 5 | `/evaluate` returned 500 on a non-object body, non-numeric `attempts`, and oversized values | Medium | Strict validation, 422 |
| 6 | JSON with unpaired surrogates caused 500 on `/evaluate`, `/v1/analyze`, `/beta/*` (response or storage encoding) | Medium | Refused with 422 before any endpoint runs |
| 7 | CORS default `*` with `allow_headers=*` | Medium | Closed by default; explicit origins; `*` refused in production |
| 8 | No request body limit | Medium | 256 KiB cap; chunked bodies refused |
| 9 | Rate-limiter dictionaries grew without bound per address | Medium | Bounded, pruned limiter |
| 10 | `/docs`, `/openapi.json` public in production; docs page loads a public CDN | Low | Off in production |
| 11 | `/status` disclosed the environment name | Low | Removed |
| 12 | Vendor-internal `/beta/business-proof` readable by any customer key | Medium | Operator key only |
| 13 | Malformed `BETA_KEYS_JSON` silently produced an empty registry (silent lock-out); weak keys accepted | Medium | Startup fails with a clear message; production key-strength rules |
| 14 | Data files created with default umask; one torn line made every summary endpoint fail | Medium | `0600`/`0700`; tolerant reads; single-write appends |
| 15 | Default bind `0.0.0.0` in the module entry point | Low | `127.0.0.1` (the container sets `0.0.0.0` explicitly, behind the proxy) |
| 16 | Missing HSTS, API CSP and `Cache-Control: no-store` | Low | Added to all responses |
| 17 | Environment settings (`SENTINEL_*`, `SENTINEL_WEBHOOK_URL`) documented but ignored by the API | Low (integrity of claims) | `SENTINEL_*` now applied; webhook variable removed because the feature is not wired |
| 18 | Analysis response contained invented figures (ticket counts, 30-day history, affected users, downstream services) | High (trust) | Removed; response reports only observed or derived values; tests guard it |

Checked and found clean: secrets and personal data in the tree and history (none; author identities are the
repository owner's public ones); path traversal (no user-controlled paths); SSRF (no URL fetching); XSS in Missions
(`textContent` only, strict CSP); unsafe deserialization (JSON only); dependency vulnerabilities (`pip-audit`: none).

Not done: independent penetration test; fuzzing beyond the hostile-input cases in the tests; formal ASVS assessment.
